## 1. Research problem and actual methodology
Uses an RL-trained Memory Manager choosing ADD/UPDATE/DELETE/NOOP and an Answer Agent selecting relevant entries. Training uses outcome-based optimization (PPO/GRPO) and evaluates long-memory QA across LoCoMo, MSC and LongMemEval; authors report generalization after training from 152 QA pairs.

## 2. Findings supported by the assessed source
The method optimizes response-level reward in benchmark QA and does not prove online updates are safe for real user preferences or external actions. Deletion requires consent/provenance semantics, not just expected answer accuracy.

The findings apply to the paper's studied population, benchmark and method. A derived design for Routin is an engineering hypothesis, not an observed effect of the paper.

## 3. Assumptions, caveats and counterexamples
Routin should specify memory write operations as typed, logged transitions; start with deterministic evidence promotion and offline evaluation before attempting RL on user data. Separate memory-utility reward from downstream authorization constraints.

## 4. Consequence for Routin's cognitive architecture
Link to AdaMEM P045 for task-time adaptation and MemPABench P041 for the gap from memory quality to realized behavior. Memory R1 cannot replace explicit temporal invalidation rules.

## 5. Cross-paper mechanism and what it enables
Compare learned manager to explicit rule policy under revocation, contradictory preferences and identical downstream task evaluation; report stale-memory harm, write cost and false permission promotion.

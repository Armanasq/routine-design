## Exact problem tested
MemPABench evaluates how personal agents learn interaction preferences: whether to clarify, confirm, act, elaborate, or contact others. Four simulated users have 14 attributes across work and personal contexts; 99 sessions per user span four months, including five scripted preference changes. The authors evaluate multiple memory backends and model backbones on preference selection, context sensitivity, temporal change tracking and actual behavioral realization.

## Published findings and boundaries
Authors report approximate aggregate preference selection: file memory 59.2%, Mem0 50.0%, MemOS 50.0%, simple RAG 49.9%, no memory 49.6%. File memory improves selection but can apply preferences in the wrong context; the reported context-sensitivity metric is low. The study uses only four simulated users and simulator/LLM-scored aspects, so the reported numbers cannot be transferred directly to live users.

## Architectural insight
Memory retrieval, policy selection and actual behavior are distinct stages. Storing a preference not to be asked repeated questions is useless if the agent still produces repetitive confirmations by habit. Routin should resolve the currently scoped preference before generation and enforce it on outputs/tool plans after generation, subject to nonnegotiable permission gates.

## Why this changes our test plan
Separate preference retrieval accuracy, context-appropriate selection, temporal preference evolution and realized interaction behavior. Log corrections and presentation-policy exposure. Benchmark on MemPABench when feasible and with real consented pilots.

## Negative case
The user likes terse replies for work messages but wants detailed explanation for personal learning. A global brevity preference would incorrectly oversimplify both. A preference for autonomous scheduling does not authorize contacting an unknown recipient.

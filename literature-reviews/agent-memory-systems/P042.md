## Research emphasis
This 2026 preprint provides a systems-oriented memory taxonomy and phase-aware profiling of ten representative memory systems across two benchmark suites. Its stated purpose is to quantify where memory work moves cost among construction, retrieval and generation. Full text and measurements have not been independently inspected in this review.

## Routin system consequence
A memory architecture is not a vector database. It is a set of operational processes with different freshness and cost requirements. The decision engine should read small structured current-state projections; source evidence must remain provenance-traceable; expensive episodic consolidation can be asynchronous. An urgent belief invalidation must not wait for the next summarization batch.

## Cross-paper link
Memora (P023) demands invalidation of stale facts; MemPABench (P041) demands correct behavior when the fact is available; this paper motivates measuring memory write, read and consolidation costs separately.

## What can go wrong
A system that improves long-context recall may increase decision latency or keep obsolete preference summaries cached after the source changed. More stored text is not necessarily better operational memory.

## Discriminating benchmark
Measure construction token/cpu cost, update-to-valid-read latency, retrieval p95, stale preference error, source revocation propagation and cost per verified responsibility. Do not select memory middleware without end-to-end comparison.
